# Next product increment: library, voice and scout experience

Discussion assessment, 2026-09-12. This records the user's questions and desired direction; it does not claim the proposed features are implemented. The existing local-first contract remains in force.

## Multiple learning books and a lasting collection

Keep IndexedDB. Today one atomic workspace record contains one curriculum and its learner state. The limitation is this data model, not JSON file size. Introduce an additive local-library/profile version containing indexed books and a selected-book ID, per-book learner/session state, local import metadata and global stamp awards. Migrate the existing workspace transactionally with rollback/error preservation. Continue accepting existing curriculum/backup files; define a full-library/profile backup for all books and collected stamps. A new course import must add a book by default. A matching course ID/version offers opening/updating deliberately; revised answer semantics must not silently reuse incompatible progress.

A book card uses curriculum.title (already required), subject/target language, reliable source page hints, importedAt generated by the app and last-practised information. Allow title editing without changing stable identity. Example: Französisch · Unité 2: À l’école · S. 12–15 · importiert 12.09.2026. Never invent unreadable book/page titles. Stamps reference their earned book/session but remain in the global profile when switching or removing a book. Award IDs prevent duplicate awards on reload or repeated imports. Store artwork once in app assets, only IDs/earned timestamps/provenance in learner data.

Browser-local storage is not an absolute guarantee against user data clearing, browser eviction or device loss. A complete profile backup is part of collection persistence. Do not describe browser storage as indestructible or device synchronization.

## Device speech

Use standard window.speechSynthesis and SpeechSynthesisUtterance with explicit language tags (fr-FR, en-GB, de-DE), selecting only voices actually returned by getVoices. Handle delayed voice lists, cancellation, errors and missing suitable voices. Start on a user tap; cancel when changing exercise/course. Keep German instructions and target-language examples separate. The current helper does not set lang and is not a completed voice feature. On iPhone we can request available system voices, not promise access to a specific Siri voice. Offer offline/local voices where available and verify the actual iPhone in flight mode; no silent fallback to a remote voice.

## Sharing and measured QR limits

Measured current fixtures with JSON.stringify, gzip and unpadded base64url:

| Fixture | Compact UTF-8 JSON | gzip | gzip as base64url |
| --- | ---: | ---: | ---: |
| English Unit 1A, 59 exercises | 30,197 bytes | 5,476 bytes | 7,302 characters |
| French technical fixture, 5 exercises | 3,233 bytes | 1,245 bytes | 1,660 characters |

A maximum-size QR symbol stores up to 2,953 bytes at its lowest error-correction level; a practical camera-friendly code should carry less. A URL hash is a possible transport for compressed, encoded curriculum, but it does not expand the capacity of a QR containing that URL. The complete English fixture does not fit in one standard QR with this encoding; the tiny French fixture may, with dense-symbol/device testing required. For larger books use existing file/text transfer, or deliberate static hosting of shareable curriculum and a short URL. Multi-frame QR is a separate scanner/protocol project and is not the first choice. No learner/profile data in sharing links by default; fragments are not sent in the HTTP request but remain visible to page scripts and anyone receiving the link. Decode size caps and existing validation/preview must precede import.

Sources: https://www.qrcode.com/en/about/versionPage/versionPage31_40.html ; https://developer.mozilla.org/en-US/docs/Web/URI/Reference/Fragment ; https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API

## Mountain route, Bergzeit and collected stamps

Reference images directly re-inspected: duolingo-learning-path.png, duolingo-gem-reward.png, duolingo-monthly-mission.png. Useful patterns: clear current path position and one next action; reward gets its own large visual moment; earned/next collection status is visible. Create original scout assets and preserve voluntary pacing without countdown pressure or loss of earned items.

Use a small SVG elevation route with one waypoint per exercise and an accessible completed/total label. Show completed work, not arbitrary proficiency elevation. An optional midpoint bench/rest screen appears only in sufficiently long rounds, once, between answered tasks. Never interrupt typing, speech or feedback. Name: Bergzeit; explain with “Kurz verschnaufen”. Let the child continue or finish later without a minimum wait. Example honest copy: “Du hast 6 Aufgaben geschafft. Noch 4 bis zum Ziel.” Only display active learning minutes after implementing a foreground/interaction-aware timer; exclude hidden tabs and breaks, and persist an acknowledged midpoint so reload does not replay it.

Initial original stamp family: a curious fox, cosy tent, little compass, backpack, pine cone and mountain bird. Award visible effort milestones (first completed round, returning to a review, several completed rounds) with clear rules, rather than random scarcity or perfect-only conditions. Present each new stamp prominently at completion and in a persistent album reachable from home. Preserve earned stamps across subjects and books. Existing numeric gems count is not an illustrated collection; migrate without claiming detailed historic artwork awards that were never recorded.

| Before | After | Why |
| --- | --- | --- |
| Small numeric stamp count | Latest earned stamps and an album entry | Make effort visible and personally meaningful |
| Plain session bar | Waypoint moves along an elevation route, keeping numeric progress | Connect progress to the product's path metaphor |
| Generic completion | One short stamp impression, then placement in the album | Explain what was earned and where it remains |
| Frequent/repeated visual motion | Brief touch feedback; transitions do not delay the next answer | Keep frequent learning interactions responsive |

Follow Emil design-engineering guidance: mostly transform/opacity; press response around 100–160 ms, short state transitions around 150–250 ms; no repeating decorations, no forced animation waits, stable keyboard focus, reduced-motion alternatives. The mountain drawing is code-native; the bench and stamp illustrations are new image-generation work in implementation, not already-made deliverables.

## Math scope

The engine's concepts, prerequisites, sessions, review and profile are reusable. Add explicit subject metadata and a math authoring contract with a versioned schema extension. Math is not a fake language code. First pilot should cover one actual school topic with numeric/choice exercises. Numeric evaluation must deliberately handle decimal comma, signs, equivalent fractions, units and when rounding/tolerance is permitted. General algebra equivalence, arbitrary work-step grading, geometry and handwriting are separate larger projects. Never use eval on imported expressions. Decide the first topic from supplied school material; do not invent its content.

## Proposed sequence and acceptance

1. Local library + full profile backup + persistent stamp award model. Verify old backup migration, safe switching, revisions and retained collection.
2. Mountain round + optional Bergzeit + first original stamp set and album. Verify no duplicate awards/pause replay, keyboard/mobile, reduced motion and elapsed-time honesty.
3. Device speech with explicit language and actual-iPhone verification. No unsupported offline claims.
4. Real parent/child pilot; fix confusing learning/authoring behavior before broader content.
5. Bounded math pilot and optional compact sharing, after the core learning experience is stable.

Stable public deployment remains a prerequisite for distributing the test. Current Pages-source conflict is tracked separately in publication.md. No new backend or account is needed for items 1–3.
