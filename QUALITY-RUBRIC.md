# First milestone quality rubric

A criterion passes only with recorded execution or inspection evidence. Material failures must be corrected before the milestone is claimed.

| Area | Required check |
| --- | --- |
| Curriculum | Inspect supplied pages; original exercises with stable concepts and provenance; no fabricated audio or long copied text. |
| Schema | Fixture validates; reject unsupported versions, broken references, ambiguous answer data and incompatible learner state. Friendly import errors preserve existing data. |
| Learning | Deterministic sessions use mastery, due dates, mistakes and difficulty; multiple types; explain answers; self-check does not imply objective grading. |
| Function | Start and complete lesson; reward once; answers persist; reload; export; restore in a fresh browser. |
| Offline | Production shell loads once, service worker activates, reload and complete practice offline. |
| UX | Clear current task and action; explicit progress, error recovery and finish screen; import/export discoverable. |
| Visual | Shared tokens/components; inspect desktop, tablet and narrow phone; no overlap or horizontal overflow. |
| Accessibility | Semantic controls, keyboard completion, focus visibility/continuity, live feedback, text with colour, 44px targets, sufficient contrast, reduced motion. |
| Privacy | No external requests in production; browser-only storage, explicit backup action, imported strings rendered safely; no reference photos in build. |
| Engineering | Critical automated tests and production build pass; independent review finds and closes material issues; README enables continuation. |

Evidence and limitations are recorded in experiment/evaluation.md. Browser automation evidence complements, rather than replaces, visual inspection and independent review.
